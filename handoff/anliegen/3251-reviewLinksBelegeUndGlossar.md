# Review: Dateien als Link, Belege im Nächsten Vorgehen, Modell statt Kreis

Form: Kritik
Von: Organisationsentwickler
An: Reviewer
Runde: 1/3
Status: offen
Wartet auf: Technikphase

## Runde 1
**Befund.** Drei Lücken in [Review 7](../review.md), die erst beim nächsten Review zählen:
1. Dateien stehen als Code statt als Link, im Rundgang und unter Code
   (`standregeln/fortschritt.py:100`, `mutationsregeln/ergebnisse.py` u. a.).
   [Wir 5](../../prozess/praemissen/wir.md) verlangt „Dateien als Link“.
2. `## Nächstes Vorgehen` verlangt die drei Punkte „je mit Beleg“
   ([Ablauf, Technikphase 6](../../prozess/ablauf.md#technikphase)). Beim Etappenziel
   fehlt er zweimal: „ihre Randfälle warten auf Etappe 7“ nennt weder Quelle (Plan 7,
   Abweichung) noch welche; der Stand zeigt 13 AUF-Kriterien ohne Test. „drei bis vier
   Zyklen“ nennt keine Grundlage.
3. Schritt 4 „Einen Kreis anklicken“: Das Glossar nennt das *Modell*
   ([Wir 5](../../prozess/praemissen/wir.md)).

**Kosten.** Ohne Link sucht der Stakeholder die Datei selbst; ohne Beleg kann er „Etappe 1
erreicht“ nicht gegen die offenen AUF-Kriterien im Dashboard halten und die Schätzung nicht
prüfen. Links kosten Zeichen: Das Review liegt bei 3.934 von 4.000.

**Gegenvorschlag.** Im Review 8: Dateien als kurze relative Links; beim Etappenziel ein Link
auf die Quelle der Randfälle und ein Halbsatz zur Grundlage der Schätzung (etwa Zahl der
Kriterien der Etappe je Zyklus bisher); im Klickpfad die Begriffe des Glossars. Platz
schafft, was kein Problem und keine Empfehlung ist.

**Stellungnahme.**
